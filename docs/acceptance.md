## 自动化验收

| 项目 | 设置 / 故障 | 通过标准 |
| --- | --- | --- |
| 链接约束 | BV、普通页面、p 参数、非法主机和非法 P | 规范化正确；仅接受支持的页面；不把任意链接交给下载器 |
| 分 P 隔离 | 同一 BV 的 P1/P2、不同 CID | 分 P、格式、临时文件及输出互不混用 |
| 格式选择 | 混合编码、同档多帧率、目标档位缺失 | 选择规则确定；兼容编码优先；缺失目标不会静默降级 |
| 权限与试看 | DRM、不可访问格式、时长不足 | 不绕权限；不把预览或残缺内容当作完整成品 |
| 持久化 | 保存任务、重启、非法记录 | 可读取合法任务；中断状态转为等待恢复；损坏记录给出错误 |
| 基本下载 | 完整 200、合法 206、未知长度 | 内容与预期一致；未知大小不伪造精确百分比 |
| Range 续传 | 中断后同一资源、可靠校验信息 | 从合法字节位置继续，最终字节及内容一致 |
| 服务器忽略 Range | 带 Range 请求返回 200 | 不把完整响应追加到旧文件 |
| 范围错误 | 206 起点错误、总长度变化、非法 Content-Range | 不继续写入不一致的字节 |
| 已下载与 416 | 文件恰好完成、文件过长、资源变化 | 区分完整与异常；无法确认时安全重下 |
| 地址刷新 | 403/404/410、新 URL、格式或资源变化 | 有限刷新；一致性不明时不拼接旧数据 |
| 校验信息不足 | 无强校验信息、弱 ETag | 不承诺安全原位续传，采取安全重新下载 |
| 重试边界 | 超时、500、429、Retry-After | 共享预算限制总重试；尊重等待；暂停可以打断等待 |
| 暂停取消 | 下载、校验、合并中触发 | 能停止当前操作，保留可复用文件，状态与操作一致 |
| 已完成流复用 | 视频或音频已完成，另一条失败 | 检查有效后复用；被修改或损坏则不复用 |
| 文件管理 | 中文、非法字符、保留名、长标题、重名 | 路径可用，不覆盖已有成品，任务拥有独立临时目录 |
| 单 P 闭环 | 本地分别生成视频与音频 | 封装成含两路流的 MP4，无重新编码 |
| 合并失败 | FFmpeg 非零退出、进程中断、临时文件残留 | 不标记完成，保留输入，可重新合并 |
| 媒体验证 | 缺音频、错分辨率、时长异常 | 拒绝提交错误文件；存在两路流不代替解码验收 |
| 成品提交 | 重名、提交前中断、提交后数据库未更新 | 不覆盖；重启可核对真实文件并恢复正确状态 |
| 队列容错 | 成功、失败、暂停任务混合 | 失败 P 不影响其他任务；不会重复并发执行同一任务 |
| 日志脱敏 | 签名 URL、Cookie、授权字段 | 导出日志不包含播放地址参数或授权内容 |
| 界面启动 | Qt offscreen --smoke-test | 构建界面并在限时内退出，不自动下载视频 |

测试未实际覆盖的行必须单独标为待验收，不能因 CI 总体变绿就默认全部通过。

续传边界：强 ETag、总长度和 CID/格式身份用于判断是否可以继续写入；ETag 不是远端内容的加密真实性证明。已完成流的本地 SHA256 用于缓存完整性检查，未完成 .part 暂无独立前缀校验。

## 0.1.1 解析修复与本地验证（2026-10-05）

在用户 Windows 11（10.0.26200）、Python 3.14.4 环境复现了用户提供的视频：yt-dlp 能返回 `BV1BLA2eFEoC` 的 15 个格式，但应用随后额外调用的 `x/web-interface/view` 返回 HTTP 412。因此本次根因是应用把额外 API 的失败升级成整个解析失败，不能仅解释为“yt-dlp 不支持”或“等待即可恢复”。

元信息改从正常公开页面的 `window.__INITIAL_STATE__.videoData` 读取，仍校验 BV、CID、P、完整时长及支持的内容类型；不执行页面脚本，不读取浏览器账号或导入 Cookie。支持服务端 gzip 页面，并限制解压后的读取大小为 4 MiB。公开元信息最多缓存 32 个 BV、30 秒，缓存不包含播放地址；列出 P 不再请求播放格式，格式仍按所选 P 通过 yt-dlp 获取。HTTP 错误保留失败阶段和具体状态码，错误文本中出现的 BV 数字或签名 URL 不用来猜测 HTTP 状态。

本地回归：2026-10-06 共 124 项自动化测试通过（6.82 秒），覆盖本地 HTTP 与 FFmpeg 引擎回归、新元信息流程的 gzip、缓存失效、重定向、大小限制、身份/权限/试看约束、412/429 区分及错误信息脱敏，以及无 stderr 的打包启动失败处理和 ICU 搜索路径隔离。

真实任务通过生产 DownloadManager 执行，限定 32 MiB、5 分钟，结果：

| 样本 | 结果 |
| --- | --- |
| BV1BLA2eFEoC P1 | 匿名解析、下载、两路输入检查、无损 MP4 封装、成品检查、提交全部成功 |
| 媒体 | H.264 + AAC，像素高度 640，帧率 30，时长 264.428617 秒 |
| 字节 | 两路下载 16,046,158；包括探测读取 16,046,162；MP4 16,220,578 |
| 完整解码 | FFmpeg 分别映射音视频流，`-xerror` 完整解码退出码 0 |
| 清理 | 测试临时目录及媒体已清理；仅保留脱敏 JSON 结果 |

这证明该样本在本次用户网络上通过真实闭环。其他 BV、多 P 实网下载、最高画质、播放器音画同步、实网暂停/恢复、无开发依赖的干净 Windows 10/11，以及版本替换后的任务保留仍需相应验收，不能由本次成功自动判定通过。

## 0.1.1 本地便携包修复（2026-10-06）

初次本地打包失败，原因是构建环境 PATH 中 Poppler 的 `icuuc.dll` 导出 `ucnv_open_78`，而 Qt6Core 请求 Windows ICU 的 `ucnv_open`。源码能启动，但 EXE 发生 DLL 入口点错误。仅在 PowerShell 中设定 PATH 未生效；现由 Python 构建进程内隔离 PATH，依赖搜索不再纳入 Poppler ICU。

Windows 11、Python 3.14.4、PyInstaller 6.22.3、Qt 6.11.2 下重新构建成功。构建清单中没有 Poppler、icuuc.dll 或 icudt78.dll，使用操作系统提供的 ICU；Qt 插件、内置 FFmpeg/ffprobe、第三方许可材料保留。实际打包 EXE 的 offscreen 启动检查退出码 0。此项验证当前用户机器上的启动，不替代干净 Windows 10/11 的完整人工验收。
